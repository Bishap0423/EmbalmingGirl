# 测试策略

## 1. 测试层级

### 单元测试

- 组牌与发牌
- 每种命令的合法性
- 每种能力 handler
- 玩家视图的信息裁剪
- MP、监禁和胜利优先级

### 场景测试

使用 Given / When / Then 固定对局状态，不依赖 UI：

- 感染者在下回合取回调合牌
- 感染者使用后立即退场，不触发能力
- 宇宙人对秀才制造假信号
- 犯人通过归宅部进入调合区
- 新闻部跳过锁手玩家并同时传递
- 保健委员不能回收保健委员
- 所有人疑惑相同，无人监禁
- 负 MP 疑惑按 0 计
- 犯人与共犯者同优先级共同获胜
- 高优先级产生胜者后停止判断
- 没有任何胜者时全灭

### 属性与模拟测试

自动生成合法行动并运行大量对局，持续验证：

- 卡牌实例总数恒定。
- 一张实例恰好位于一个区域。
- 只有当前玩家可以提交普通回合行动。
- 标准模式锁定手牌不被移动。
- 终局一定发生在所有玩家退场之后。
- 同种子、同命令序列的事件和状态哈希一致。
- 任意玩家视图不包含未授权卡牌定义 ID。

### 协议测试

- WebSocket 消息 schema
- stale revision
- 重复 request ID 的幂等处理
- 私密事件只发往授权连接
- 重连 snapshot 与在线状态一致

### 端到端测试

- 创建房间、多个浏览器加入并开始
- 三种出牌方式
- 至少一个多步骤、一个同时选择和一个私密查看能力
- 所有人退场并显示正确终局
- 中途刷新页面继续待决策

## 2. 隐藏信息测试

隐藏信息泄漏属于阻断发布的问题。测试不能只断言 UI 没有显示，还应检查原始网络负载：

- 对每个事件分别投影成每名玩家的消息。
- 搜索其他玩家手牌实例对应的角色 ID、名称、图片 key 和能力 key。
- 检查错误消息不会因不同隐藏牌返回不同细节。
- 检查合法行动列表不会替其他玩家枚举可选牌。

## 3. 终局测试矩阵

| 情况 | 预期 |
|---|---|
| 宇宙人被监禁，同时其他角色满足条件 | 宇宙人以优先级 1 获胜 |
| 宇宙人未赢，调合失败 | 所有以感染者为最后手牌且合格的玩家获胜 |
| 调合成功、犯人未监禁 | 犯人及共犯者按优先级 3 获胜 |
| 犯人被监禁、调合成功 | 满足条件的优先级 4 角色获胜 |
| 优先级 1–4 均无人满足 | 归宅部持有者以优先级 5 获胜 |
| 没有归宅部且无人满足 | 全灭 |

## 4. 发布门槛

- 后端分支覆盖率目标不低于 90%，规则核心应接近 100%。
- 所有角色至少一个独立场景。
- 所有已确认规则疑问关闭或显式记录为版本化裁定。
- 不存在高优先级隐藏信息、状态损坏或不可恢复卡局缺陷。
