# 开发里程碑

估算以一名开发者连续实施为基准，不包含大模型接入和正式美术制作。总计约 7 个工作日，另保留 2–3 天验收修整。

## M0：工程基线与规则冻结

预计：0.5 天

交付：

- Python 与前端工作区
- 格式化、静态检查和测试命令
- 13 种角色数据文件
- 规则来源、版本及待确认项登记
- 临时素材目录与清单，不把 PDF 直接耦合进规则代码

验收：

- 后端和前端均可一条命令启动
- CI 等价的本地检查全部通过
- 卡牌数量合计为 25，各人数牌组断言通过

## M1：纯 Python 核心回合

预计：1 天

交付：

- `GameState`、Command、Event、Reducer
- 按人数组牌、固定种子洗牌和发牌
- 特技、调合、疑惑三种基础行动
- 退场、锁手、跳过退场玩家和终局触发

验收：

- 无 Web 环境可运行完整的无能力脚本局
- 相同种子和命令产生完全相同事件
- 非法行动不会改变 state 或 revision

## M2：全部角色能力

预计：1.5 天

交付：

- 13 种角色能力
- 私密查看、双方交换、同时传牌、随机抽牌
- 感染者延迟触发
- 秀才与宇宙人的私密信号流程
- 标准模式与 Chaos Mode

验收：

- 每个能力至少覆盖正常、无目标、锁手三个相关路径
- 所有多步骤能力可在任一步序列化并恢复
- 隐藏信息不进入无权限玩家事件

出口门槛：

- 确认最终中文角色显示名；内部 ID 可先冻结

## M3：终局、回放与属性测试

预计：1 天

交付：

- 调合、监禁、五级胜负判定
- 共犯者依赖犯人的同优先级判断
- 全灭结局
- JSONL 事件日志、快照和重放
- 规则不变量与随机模拟

验收：

- 规则文档中的终局案例全部通过
- 任意模拟局始终保持每个卡牌实例只存在于一个区域
- 回放状态哈希与原局一致

## M4：本地房间与实时服务

预计：1 天

交付：

- 创建、加入、准备、开始房间
- WebSocket 命令和玩家视图
- revision 并发控制
- 断线重连与 pending decision 恢复

验收：

- 3–6 个浏览器会话可完成脚本对局
- 抓取任意玩家消息都不能还原其他玩家暗牌
- 重复、乱序和过期命令不会重复结算

## M5：Web 游戏界面

预计：1.5 天

交付：

- 房间、牌桌、手牌和三区域
- 合法行动、目标选择、能力决策弹层
- 私密查看、回合状态和终局页面
- PDF 临时卡图接入与缺图占位
- 基础响应式布局和键盘可操作性

验收：

- 不查看服务端日志即可完成一局
- UI 只允许选择服务端提供的合法选项
- 正式素材可通过替换 manifest 切换，无需改组件

## M6：联调、验收与交付

预计：0.5 天

交付：

- 端到端核心路径
- 本地启动与故障排查文档
- 规则差异和剩余问题清单
- 可供未来模型使用的 observation / legal actions 演示

验收：

- 3、4、5、6 人各完成至少一局自动化对局
- 浏览器刷新和服务重启恢复测试通过
- 全部 lint、类型检查、单元、场景和 E2E 检查通过

## 建议验收缓冲

预留 2–3 天用于：

- 与实体规则进行人工对局比对
- 修正规则翻译或能力边界
- 正式美术第一轮适配
- 浏览器兼容和交互细节修整

缓冲不是新增功能预算。若加入公网部署、账号、聊天、观战或 AI，应另建里程碑。
