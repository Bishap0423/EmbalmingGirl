# 产品范围与开发原则

## 1. 产品目标

在本地运行一局 3–6 人的《冰冷的她醒来之前》：

1. Python 引擎负责洗牌、隐藏信息、行动校验、能力结算与胜负判定。
2. 多个 Web 客户端加入同一房间，每个客户端只看到自己有权查看的信息。
3. 对局可由固定随机种子复现，并可通过事件日志回放。
4. 人类玩家和未来的模型玩家使用同一套结构化行动接口。

“未来可接入模型”在本阶段只意味着接口边界稳定，不包含模型 SDK、提示词、记忆、推理服务、费用控制或内容安全系统。

## 2. 首个正式版本范围

### 包含

- 3、4、5、6 人标准规则
- 可选 Chaos Mode
- 本地房间创建、加入和准备
- 私密手牌、私密查看与公开区域
- 13 种角色、25 张卡的完整结算
- 合法行动提示和服务器端强校验
- 断线重连、当前状态恢复
- 对局事件日志、固定种子与回放
- 桌面浏览器布局；手机端保证可操作，不追求首版精细适配
- 临时卡图与后续正式素材的无代码替换

### 不包含

- 公网账户、匹配、排行榜、好友系统
- 观战、语音或自由文本聊天
- 服务端长期运营、反作弊和多实例部署
- 大模型接入
- 原作规则以外的新角色和平衡性修改
- 原作实体组件的印刷复刻

## 3. 权威性原则

- 服务器状态是唯一权威状态，客户端不得自行完成规则结算。
- 规则优先级：日文官方规则书 > 日文卡面 > 英文译本。
- 英文 PDF 存在机器翻译式用词，不直接作为标识符或裁定依据。
- 所有随机行为均使用对局专属伪随机源，并记录种子及随机结果事件。
- 卡牌实例与卡牌定义分离：定义说明“是什么”，实例说明“这一张在哪里”。
- UI 不根据角色名硬编码能力流程；引擎通过待处理决策描述驱动 UI。

## 4. 完成定义

首个正式版本必须满足：

- 所有玩家人数配置下，牌数可整除且起手牌数符合规则。
- 13 种角色的正常路径、无合法目标路径和边界路径均有自动化测试。
- 客户端无法通过公开状态接口获得他人手牌或暗置牌身份。
- 同一种子与同一行动序列产生完全一致的事件与终局。
- 断线后可恢复至当前待决策步骤。
- 美术文件替换不要求修改 Python 或 TypeScript 规则代码。

## 5. 已知风险

| 风险 | 处理 |
|---|---|
| 日英译名不一致 | 内部使用稳定英文 ID，界面文本走本地化表 |
| 实体游戏中的闭眼、吐舌等动作无法直接搬到 Web | 转换为服务器主持的私密信号阶段 |
| 多步骤能力在玩家断线时卡住 | 每一步形成可持久化的 pending decision |
| PDF 临时图片未来被替换 | 单独资源目录、清单和固定槽位规格 |
| Chaos Mode 会改变最后一张牌的保护规则 | 作为房间级规则开关，不散落在能力代码中 |
